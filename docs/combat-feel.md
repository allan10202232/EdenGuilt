# 动作手感与环境融合

2026-10-18，本轮沿用双形态角色与三关场景，补绘连续动作并调整操作反馈。

## 操作与节奏

- 左键短砍：前摇 60ms、生效 100ms、后摇 120ms、冷却 80ms，完整周期 360ms。
- 右键长砍：前摇 180ms、生效 140ms、后摇 200ms、冷却 140ms，完整周期 660ms。
- 鼠标输入保留最近一次 140ms 内的攻击请求；只在共享动作锁结束后执行，过早的请求自然过期。拒绝或排队本身不计碳排，真正出刀时计一次。
- 受伤、开盾、矿化、黑穿、抽取、剧情及关卡卸载清除待执行攻击。
- 轻按空格小跳，按住高跳；松开将上升速度限制到原起跳速度的 55%。离地宽限 100ms、跳跃缓冲 120ms 保留，命中停顿期间的跳跃输入也可缓冲。
- 起跳速度、重力、移动速度、攻击范围和伤害不变。正常输入路线明确按住高跳，仍需学习二段跳和矿化才能越过关卡断口。

## 打击反馈

命中时，玩家、当前武器和存活目标短暂停顿：普通命中约 35ms，长刀约 45ms，击杀约 55ms（物理上按 60Hz 帧量化）。
两种武器中空闲的一种不保留暂停，避免下一刀额外延迟。命中回调先显示挥出帧、刀光和火花，再保持姿势。
同一挥砍的目标去重贯穿暂停，恢复后不会重复伤害。目标有短暂闪白与击退，镜头约 1.8–3px 轻震并自动归零。
这是局部停顿，不修改 `Engine.time_scale`，不暂停菜单、NPC、技能获取或整个世界；碳账本和游玩时钟仍按实际游戏时间推进。

六个分层战斗声音位于 `assets/audio/combat/`：短刀、长刀、轻命中、重命中、击杀、落地。
由确定性过滤噪声、瞬态、低频冲击和衰减共鸣合成；离线重建脚本为 `assets/audio/combat/build_audio.py`，游戏运行无需 Python。

## 动画与空间

内置 image_gen 参考旧红、绿动作表，各补绘一张 `hero_red_motion.png` / `hero_green_motion.png`，保存为新文件，保留原图。
每张 1536×1024、6×4 固定格：六帧跑步；待机/呼吸/起跳/二段跳/下落/落地；六帧短砍；六帧长砍。
原表继续承担护盾、矿化、黑穿、受击、倒地；抽取保留独立六帧动作。完整提示词、引用素材与工具记录在 [motion-art-prompts.json](motion-art-prompts.json)。

`HeroActionVisual` 按真实近战阶段及其进度选帧，落地姿势不覆盖正在发生的挥砍。每帧独立脚底基准，落地轻压身、转身轻收窄、挥刀重心前移，均只改变显示。
`actor_lighting.gdshader` 为角色和敌人统一像素采样与有限色阶，清除低透明光晕，并施加少量垃圾场黄绿、矿洞冷蓝、伊甸城暖色环境光。
材质通过 vertex varying 传递染色，避免在 fragment 中二次乘入原纹理而变暗；约定见 [Godot CanvasItem COLOR 文档](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html#color-and-texture)。
武器、护盾和吸魂器对脚边地面有小范围色光；接触阴影通过实际地形射线定位，跳起后减弱、缩小，断口下无地面时隐藏。
前景草叶稀疏放置于已有可站立地面，最多遮挡脚踝，不改变碰撞或遮挡主要动作。三张 Scenario 原图、中段与平台保持原有整合。
